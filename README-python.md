# Ведомость: PDF → Word

Первая версия настольного приложения для Windows. Обработка локальная: приложение не обращается к сетевым сервисам. Импортирует спецификации ЕСКД, позволяет исправлять позиции и связи сборок, раскрывает вложенность, объединяет позиции и создаёт редактируемую ведомость DOCX на листах А3.

## Запуск из исходников

Нужны Python 3.12 с Tkinter и Tesseract OCR 5 с языками `rus` и `eng`. На машине разработки установка зависимостей требует интернета; после установки работа приложения — офлайн.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:VEDOMOST_TESSERACT = 'C:\Program Files\Tesseract-OCR\tesseract.exe'
$env:VEDOMOST_TESSDATA = 'C:\Program Files\Tesseract-OCR\tessdata'
.\.venv\Scripts\python.exe -m vedomost
```

## Использование

1. Добавьте PDF. Текстовый слой читается напрямую, сканы распознаются Tesseract. Дождитесь импорта всех файлов.
2. Для каждой спецификации откройте исходный PDF и сверьте все страницы. Обозначение сборки первоначально берётся из имени файла: замените его обозначением из основной надписи. Для раскрытия оно должно совпадать с обозначением соответствующей позиции в разделе «Сборочные единицы». При анонимизированных файлах связи задаются вручную.
3. Двойным щелчком исправьте наименования, обозначения, разделы, количества и единицы. Добавьте пропущенные позиции, удалите лишние. Поставщик не угадывается; поле заполняется при наличии данных. Для документации используется количество 0, в отчёте количество не печатается.
4. Укажите количество головных изделий. Головными автоматически считаются загруженные сборки, на которые не ссылаются другие загруженные сборки. Каждая учитывается один раз с указанным множителем. Вложенные сборки не считаются повторно как отдельные изделия.
5. Подтвердите проверку каждой спецификации. Сохраните проект JSON, чтобы не потерять исправления. PDF остаются отдельными файлами; проект содержит пути к ним, а не копии.
6. Выгрузите Word, задайте наименование и обозначение ведомости. Применяемость показывает цепочку от головного изделия до непосредственной сборки. Количества учитывают все множители в цепочке. Сборочные единицы сохраняются в своём разделе вместе с раскрытыми деталями; общий итог по разным разделам не вычисляется.

Если спецификация вложенной сборки отсутствует, программа сохраняет её как нераскрытую позицию и предлагает выгрузить неполный результат с явным перечнем таких сборок. Циклы, дубли обозначений сборок и противоречивые данные деталей блокируют расчёт.

## Сборка Windows

На Windows установите Python 3.12 x64 и Tesseract OCR 5 x64 с русским и английским языками из доверенного источника. Выполните:

```powershell
.\build_windows.ps1 -TesseractDirectory 'C:\Program Files\Tesseract-OCR'
```

Результат — папка `dist\Vedomost` с `Vedomost.exe`, Python-библиотеками, OCR и языковыми моделями. Переносите папку целиком. На целевом ПК Python и интернет не нужны; для просмотра и редактирования результата нужен Word или совместимый редактор. Сохраняйте лицензии зависимостей при распространении; PyMuPDF распространяется по AGPL либо коммерческой лицензии.

Скрипт сборки подготовлен, но создание и запуск EXE в Windows ещё не проверены. Эта Linux-среда не может подтвердить Windows-совместимость готового пакета.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют множители вложенных сборок, разные пути входимости, объединение повторов, точность дробных количеств, различия размеров и единиц, циклы, конфликты, нераскрытые сборки, сохранение проекта и структуру Word.

## Ограничения первой версии

- Импорт рассчитан на вертикальные таблицы ЕСКД, подобные предоставленным образцам. Повернутые страницы, нестандартные колонки, продолжения позиции через границу страницы и плохие сканы могут потребовать ручного ввода. Любой импорт требует проверки; распознавание не гарантирует полноту.
- Одинаковые детали и сборки определяются по обозначению и единице. Для стандартных изделий и материалов дополнительно сравнивается полное наименование, включая размеры. Разные написания автоматически не сближаются, чтобы не объединить разные изделия.
- Формат Word воспроизводит основные колонки, разделы, строки применяемости, итоги, рамки А3 и упрощённые основные надписи. Это не точная копия формы: боковые инвентарные графы, полный штамп первого листа и лист регистрации изменений ещё не реализованы. До выпуска документа требуется сверка оформления в Word.
- Пользовательские PDF и образец DOC не включены в исходники.

# Ведомость — браузер и Windows

Одна программа для объединения спецификаций ЕСКД из PDF в ведомость Word. Чтение PDF, распознавание сканов, расчёты и создание DOCX выполняются локально. Внешних API и серверной обработки документов нет.

## Запуск без установки Python или Node.js

Распакуйте **всю папку** из `Vedomost-Windows-x64.zip`.

- `Vedomost.exe` открывает отдельное окно приложения.
- `Open-browser.cmd` открывает программу в обычном браузере. Локальный процесс остаётся в области уведомлений Windows; для завершения выберите «Выход» в меню значка.

Интернет не нужен даже при первом запуске: OCR, русский и английский языки, обработчик PDF и Word-шаблон включены в архив. Не переносите один EXE отдельно. Пакет предназначен для Windows 10/11 x64, подписи издателя нет. Нативный запуск и браузерный сценарий Windows-пакета проверяются в GitHub Actions перед выпуском.

Локальный сервер слушает только `127.0.0.1:19745`. Настраивать его не нужно. При занятом порте приложение сообщит об ошибке. Второй экземпляр активирует существующий.

Проекты отдельного окна и обычного браузера хранятся отдельно. Для переноса используйте «Сохранить JSON» / «Открыть JSON». JSON совместим с Python-прототипом. Исходные PDF в JSON не включаются — храните их отдельно.

## Браузерная версия PWA

`Vedomost-Browser.zip` содержит готовый статический сайт. Для публикации разместите его содержимое на HTTPS-хостинге; поддерживается подпапка сайта. Двойной щелчок по `index.html` не подходит: браузер ограничивает модули и service worker для `file://`.

После первого открытия дождитесь надписи «Готово к работе офлайн». Приложение сохраняет обработчик PDF, модели OCR, шаблон и интерфейс. После этого можно работать без сети и установить PWA кнопкой «Установить» в поддерживающем браузере. Очистка данных браузера удаляет проект и офлайн-кэш; сохраняйте JSON отдельно.

Для браузера без размещения сайта используйте `Open-browser.cmd` из Windows-пакета. Публичный сайт пока не опубликован. Офлайн-режим проверен в Chromium; другие браузеры отдельно не проверялись.

## Несколько проектов

Вверху окна расположен список проектов. «Новый проект» создаёт пустую ведомость, сохраняя предыдущую в списке. Между проектами можно переключаться без удаления спецификаций. «Переименовать» меняет название активного проекта.

У каждого проекта свои спецификации, отметки проверки, количества исполнений, выбранные разделы и реквизиты Word. Изменения сохраняются автоматически; после перезапуска открывается последний активный проект. При первом запуске версии 0.5 данные прежней версии становятся проектом «Моя ведомость», а исходная запись остаётся резервной копией в хранилище.

«Открыть JSON» добавляет файл как отдельный проект, не заменяя текущую ведомость. «Сохранить JSON» скачивает копию только активного проекта с его названием. PDF в JSON не входят. Список хранится на этом компьютере в данных приложения или профиле браузера: очистка этих данных удаляет проекты. Экспортируйте важные ведомости отдельно. При нехватке места или изменении списка в другом окне переключение блокируется; текущую работу можно скачать в JSON.

## Интерфейс по схеме

Слева — загруженные спецификации. В центре — шесть разделов выбранной спецификации; щелчок по позиции открывает её для исправления в таблице. Справа — раскрываемая структура всех изделий с нумерацией и количествами «на одну сборку → всего». Щелчок в дереве открывает исходную позицию. Выбор изделия над деревом меняет только просмотр.

В блоке «Сформировать ТВК» выберите разделы для Word. Сборки раскрываются независимо от флажков: если оставить только детали, их вложенные количества сохранятся. Выбор разделов сохраняется в проекте. Одинаковые позиции объединяются с указанием непосредственных сборок.

Если браузер не запускается: распакуйте весь **Windows-архив** и запустите `Open-browser.cmd`. Пока программа находится в области уведомлений, можно вручную открыть `http://127.0.0.1:19745/` в Chrome или Edge. При неудаче автоматического открытия приложение предлагает скопировать адрес. Открытие `index.html` из отдельного Browser-архива показывает инструкцию: для работы этому архиву нужен HTTPS-хостинг или локальный веб-сервер.

## Работа со спецификациями

1. Добавьте PDF. Текстовый слой читается напрямую, сканы — через локальный Tesseract.js/WebAssembly.
2. Сверьте обозначение каждой сборки с основной надписью. Сначала используется имя файла. Для раскрытия оно должно совпасть с обозначением позиции в разделе «Сборочные единицы» другой спецификации.
3. Проверьте все страницы, исправьте названия, количества, единицы, ГОСТ/ТУ и пропущенные позиции. Если единица материала не распознана, она остаётся пустой и подтверждение блокируется. Поставщик не угадывается.
4. Укажите количество головных изделий. Головными считаются загруженные сборки, на которые не ссылаются другие сборки. Вложенные сборки повторно как головные не учитываются.
5. Подтвердите проверку каждой спецификации. На вкладке «Общая ведомость» просмотрите применяемость и итоги.
6. Выгрузите DOCX, заполнив реквизиты. При необходимости добавьте лист регистрации изменений.

Расчёты используют точную десятичную арифметику. Детали/сборки объединяются по обозначению и единице; стандартные изделия/материалы — дополнительно по полному наименованию. Латиница и кириллица в обозначениях автоматически не подменяются. Циклы, дубли спецификаций, неправильные количества и пустые сборки блокируют расчёт. Разные наименования, поставщики и примечания одинаковой позиции больше не блокируют объединение: данные сохраняются отдельно для каждой входимости в общей ведомости и Word, количества суммируются. Нераскрытые сборки сохраняются как позиции; для неполной ведомости нужно явное подтверждение, вместе с Word скачивается список таких сборок.

В разделах «Сборочные единицы» и «Детали» пробелы в обозначениях удаляются при импорте PDF/проекта и редактировании. Например, `ХХХХ. 0123456. 789` превращается в `ХХХХ.0123456.789`. Сокращённые исполнения `-01`, затем `-02` получают базовое обозначение предыдущей позиции того же раздела: `ХХХХ.0123456.789-01`, `ХХХХ.0123456.789-02`. Правило работает и на следующей странице. Если предыдущего обозначения нет, нужно ввести полное вручную. Пробелы в ГОСТ/ТУ других разделов сохраняются. Пустое наименование исполнения берётся из предыдущей позиции; количество не угадывается.

Кнопка «Добавить PDF» у сообщения «Нет спецификации» есть в дереве, общей ведомости и окне выгрузки. Выбранный файл получает обозначение недостающей сборки независимо от имени файла. После загрузки проверьте соответствие обозначения основной надписи PDF и подтвердите данные. Дерево перестраивается автоматически; если файл уже загружен с таким обозначением, повторный импорт отклоняется.

## Исполнения и горизонтальные спецификации

В Word и общей ведомости применяемость содержит только непосредственную сборку: для цепочки `A → B → C` позиция из C относится к `C`. Количество по-прежнему учитывает все уровни и суммируется, если эта сборка встречается в нескольких изделиях. Дерево сохраняет полную структуру.

Обычная спецификация с базовым обозначением используется также для её исполнений `-01`, `-02` и т.д. Повторно загружать PDF не требуется. Отдельная спецификация с точным обозначением исполнения имеет приоритет над общей. При загрузке по кнопке у недостающего исполнения файл получает базовое обозначение — его нужно сверить с PDF.

Горизонтальные групповые спецификации читаются по колонкам шапки: `—` — базовое изделие, `01`, `02` и т.д. — исполнения. На вкладке «Исполнения» видны все количества; каждая ячейка редактируется. Вложенная сборка выбирает колонку по своему полному обозначению. Для отдельного головного изделия выберите исполнение в карточке; остальные исполнения не прибавляются автоматически. В таблице количеств прочерк или 0 исключает позицию, пустая ячейка требует уточнения. Для документации X обозначает наличие документа. Если нужной колонки нет, содержимое другого исполнения не подставляется.

Проверен присланный горизонтальный PDF: 4 страницы, 14 позиций, 6 исполнений. Проверена также распознаваемость шапки растровой копии одного листа; OCR может ошибаться в количествах и названиях, поэтому требуется сверка. Несовпадающие наборы исполнений на разных страницах и нераспознанные колонки блокируют импорт, чтобы количества не смещались. Присланный PDF и его копии в репозиторий не включены.

Старые JSON-проекты открываются в новой версии. Проекты с таблицами исполнений сохраняйте и открывайте в версии 0.4 или новее: старые версии не поддерживают дополнительные колонки.

## Word-шаблон

`web/public/template.docx` подготовлен из предоставленного DOC через LibreOffice. Сохранены исходные таблицы, колонтитулы, рамки, боковые инвентарные графы, основные надписи и лист регистрации изменений. Примерные данные очищены; приложение заполняет строки и реквизиты. Рамка остаётся редактируемой, это не картинка.

Основная таблица содержит 23 строки на первом листе и 29 на последующих, с явными разрывами страниц. Применяемость и итог выводятся под одной позицией. Большой блок может продолжиться на следующем листе.

Результат проверен визуально в LibreOffice. Перед выпуском проверьте шрифты, длинные реквизиты и страницы в вашей версии Microsoft Word. Полная идентичность отображения во всех редакторах не гарантируется. Исходные размеры формы, включая лист регистрации изменений после конвертации, не переопределяются.

## Разработка и повторная сборка

Разработчику нужны Node.js 24 и npm. Пользователю готового пакета они не нужны.

```sh
npm ci
npm run build
npm test
npm run preview -- --port 4173 --strictPort
```

Сборка скачивает модели из зафиксированного коммита официального `tessdata_fast`, проверяет SHA-256 и сохраняет все OCR/PDF-ресурсы. Последующие сборки используют проверенные локальные копии. В среде с обязательным HTTP-прокси запускайте Node с `NODE_USE_ENV_PROXY=1`; TLS и контрольные суммы не отключаются.

```sh
npm run build:windows
```

Пакет появляется в `release/Vedomost-win32-x64`. Electron Packager скачивает официальный Electron 45.0.0 с проверкой контрольных сумм. Сборка из Linux не запускает Windows-программу и не заменяет проверку на Windows.

Браузерные проверки (preview уже должен работать):

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

Опционально: `VEDOMOST_FIXTURES` — каталог с двумя пользовательскими PDF, `VEDOMOST_REVIEWED_PROJECT` — проверенный JSON для экспорта, `VEDOMOST_TEST_URL` — адрес проверяемой сборки, `VEDOMOST_LANDSCAPE` — путь к горизонтальному PDF. PDF в репозиторий не включены. Проверяются офлайн-перезагрузка, отсутствие внешних запросов, сохранение проекта, вложенные количества, запрет непроверенного экспорта и XML в DOCX. С PDF-фикстурами дополнительно проверяется текстовый документ и скан без сети.

Предыдущий Python-прототип сохранён в `vedomost/`, инструкция — `README-python.md`, старый сценарий — `build_python_windows.ps1`. Для новых версий он не нужен.

## Ограничения и лицензии

- OCR ошибается. Поддерживаются вертикальные таблицы ЕСКД и горизонтальные групповые таблицы по предоставленным образцам. Поворот, другие колонки, продолжения через страницы и плохие сканы могут потребовать ручного ввода.
- Присланные PDF не содержат цепочку сборок; вложенность проверена на специальных тестовых проектах.
- Проверены Chromium/Linux и DOCX в LibreOffice. Нативный запуск EXE и браузерный сценарий проверены на Windows в GitHub Actions. Установка PWA через меню Windows и Microsoft Word отдельно не проверены.
- Локальное сохранение не заменяет резервную копию JSON.

Лицензии JS-зависимостей — `THIRD-PARTY-LICENSES.txt` в сборке, Electron/Chromium — в Windows-пакете. PyMuPDF (AGPL либо коммерческая лицензия) используется только старым Python-прототипом и не включён в новые браузерную и Electron-версии.
